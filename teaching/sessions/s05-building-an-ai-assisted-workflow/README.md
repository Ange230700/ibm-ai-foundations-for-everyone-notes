# S05 — Construire un workflow assisté par l’IA

Ce dossier contient les sources pédagogiques bilingues de la séance professionnelle S05.

La séance occupe la position **INTEGRATE** du curriculum professionnel. Elle apprend à placer l’IA
dans un processus professionnel borné plutôt qu’à traiter une interaction avec un modèle comme un
workflow complet.

La provenance canonique prévue repose sur quatre modules effectivement adaptés :

- Course 01 / Module 03 — Business and Career Transformation Through AI ;
- Course 03 / Module 02 — Prompt Engineering: Techniques and Approaches ;
- Course 04 / Module 01 — Chatbot Fundamentals ;
- Course 01 / Module 04 — Issues, Concerns, and Ethical Considerations.

Le module Chatbot Fundamentals est utilisé uniquement pour son modèle structurel d’actions,
d’étapes, de conditions et de workflows. S05 n’est pas une séance de construction de chatbot.

Le
[contrat pédagogique S05](../../../docs/teaching/s05-ai-assisted-workflow-60-min-content-contract.md)
fixe **25 diapositives** et **60 minutes** dans chaque langue.

L’
[audit de fusion](../../../docs/teaching/s05-professional-fusion-audit.md)
fixe les limites de provenance, de responsabilité humaine, de mesure et de contenu.

## Sources pédagogiques

- Français : `fr/session.md`
- Anglais : `en/session.md`

Les deux sources doivent préserver les mêmes identifiants, durées, faits fictifs, étapes du
workflow, affirmations volontairement erronées, chemins d’exception, contrôles humains et logique
de mesure.

## Cas fil rouge

La séance utilise une coopérative cacaoyère fictive près de Soubré.

Le paquet pédagogique contient notamment :

- CP-A ;
- SB-201 ;
- SB-202 ;
- 540 kg ;
- une interruption de 09:10 à 09:40 dont la cause n’est pas fournie ;
- un mouvement de SB-201 vers `Area A` à 12:15 ;
- un poids manquant pour SB-202.

Aucune règle réelle de coopérative, d’ANADER, de qualité, de paiement, de certification ou
d’approbation n’est impliquée.

## Statut de production

Ces fichiers constituent un **brouillon pédagogique bilingue**.

Ils doivent ensuite être :

1. alignés et relus ;
2. enregistrés dans `manifest.json` ;
3. validés par le parseur de séance ;
4. construits en PDF/PPTX ;
5. contrôlés visuellement ;
6. répétés avant clôture de S05.

L’attribution à IBM/Coursera et la déclaration de génération avec l’IA doivent rester visibles dans
les supports finaux.
