# S02 Professional Fusion Audit

## Status

- **Session:** S02 — Using Generative AI at Work / Utiliser l’IA générative au travail
- **Duration target:** 60 minutes
- **Slide-count target:** 26 slides in English and 26 slides in French
- **Audience:** professionals and learners with no technical prerequisite
- **Anchor case:** fictional cocoa cooperative near Soubré
- **Curriculum position:** USE
- **Parent contract:** `docs/teaching/ai-for-everyone-professional-curriculum.md`
- **Current content contract:** `docs/teaching/s02-generative-ai-60-min-content-contract.md`
- **Current teaching sources:** bilingual S02 sources under
  `teaching/courses/02-generative-ai-introduction-and-applications/`
- **Purpose of this audit:** identify what should be preserved, strengthened, compressed, or
  deferred before the S02 bilingual content contract is refactored.

## 1. Session role in the fused curriculum

S01 answers:

> What is AI, and what should I realistically expect from it?

S02 should answer:

> What can I actually do with generative AI professionally?

S03 will answer:

> How do I communicate effectively with an AI system?

S02 therefore sits between general AI literacy and detailed prompt design.

Its primary job is not to teach a catalogue of model families, tools, or prompting techniques.

Its primary job is to make generative AI professionally useful and understandable through
recognizable tasks, bounded demonstrations, review, and human responsibility.

The intended progression is:

```text
WORK NEED
    ↓
GENERATIVE TASK
    ↓
SOURCE / CONTEXT
    ↓
DRAFT OUTPUT
    ↓
CHECK
    ↓
HUMAN USE OR APPROVAL
```

## 2. Source and authority boundary

The S02 fusion uses the same three-layer authority model as the parent curriculum.

### 2.1 Canonical IBM/Coursera source

The canonical Course 02 notes remain authoritative for concepts adapted from IBM's
**Generative AI: Introduction and Applications** course within the **AI Foundations for Everyone**
Specialization delivered through Coursera.

The three canonical modules cover:

1. introduction and capabilities of generative AI;
2. applications and tools of generative AI;
3. course project, quiz, and wrap-up.

Concepts that should remain traceable to those modules include:

- generative versus discriminative AI;
- previously learned model capability versus the current request;
- text, image, audio, video, code, synthetic-data, and virtual-world outputs;
- applications across industries;
- code-generation possibilities and limitations;
- generative versus agentic AI;
- practical generation activities;
- evaluation of generated results.

The teaching session may select, simplify, reorder, and contextualize these concepts without
changing their meaning.

### 2.2 Collaborative professional-practice input

The colleague-supplied manuscript
_Cours complet : Utiliser l’intelligence artificielle dans la vie professionnelle_
contributes professional-use patterns including:

- drafting and rewriting professional emails and messages;
- producing documents and meeting summaries from supplied information;
- preparing presentation or proposal structures;
- preserving meaning while changing tone, audience, or format;
- identifying missing information instead of inventing it;
- checking names, dates, amounts, commitments, and other consequential details;
- treating generated work as a draft that requires review.

These contributions are curriculum-design input, not automatically IBM/Coursera source material.

The manuscript itself remains outside the repository unless distribution is explicitly authorized.

### 2.3 Repository adaptation

The S02 teaching session remains an independent repository adaptation generated with AI and subject
to human review.

The adaptation should combine:

```text
CANONICAL GENERATIVE-AI CONCEPTS
                +
RECOGNIZABLE PROFESSIONAL TASKS
                +
SOURCE-GROUNDED DEMONSTRATIONS
                +
HUMAN REVIEW
```

## 3. What the current S02 already does well

The current 26-slide S02 already contains a useful instructional spine.

### Generative versus other AI tasks

The current session distinguishes:

- classification;
- forecasting;
- generation.

This is a useful bridge from S01 and should remain concise.

### Model behavior

The current training-request-review sequence correctly separates:

```text
EARLIER TRAINING
    ↓
CURRENT REQUEST
    ↓
PROPOSED OUTPUT
    ↓
HUMAN REVIEW
```

This should remain because it prevents the misconception that each new prompt retrains the model.

### Source-grounded demonstration

The fictional intake instruction provides a deliberately small source:

- lot identifier;
- date;
- weight;
- incomplete records marked for completion;
- staff review.

This is effective because learners can directly compare the generated output against the source.

### Deliberately unsupported output

The invented certification-within-24-hours example creates an observable error that learners can
identify.

The sequence:

```text
SOURCE
    ↓
DRAFT
    ↓
UNSUPPORTED CLAIM
    ↓
CHECK
    ↓
CORRECTED DRAFT
```

should remain.

### Human authority

The existing session repeatedly distinguishes generated content from organizational authority.

AI does not approve:

- a lot;
- a payment;
- an inspection;
- a certification;
- publication of an operational instruction.

That boundary should remain explicit.

### Multimodal and code examples

The existing session gives learners exposure to:

- text;
- images;
- audio;
- video;
- synthetic data;
- code;
- agentic systems.

These concepts are useful, but their treatment should support the professional-use objective rather
than dominate it.

### Existing teaching assets

The current visual system already supports:

- model/request/review;
- audience/output/check;
- the real ChatGPT staff-notice exchange;
- a deliberately wrong output;
- a review sequence;
- a corrected output;
- poster review;
- local HTML guide;
- agentic actions.

Where the revised slide purpose remains compatible, existing assets should be retained or adapted
rather than replaced without need.

## 4. Main fusion gap

The current S02 demonstrates generative AI effectively but does not yet make ordinary professional
use sufficiently visible.

A learner should leave S02 recognizing generative AI in work such as:

```text
EMAILS AND MESSAGES
MEETING NOTES AND SUMMARIES
REPORTS AND DOCUMENTS
PRESENTATION OUTLINES
REWRITING AND TONE ADAPTATION
VISUAL COMMUNICATION
CODE OR SIMPLE TECHNICAL AIDS
```

The cocoa cooperative remains the anchor case, but it should no longer carry nearly the entire
professional-transfer burden.

S02 should make clear that the same principles apply to administration, customer service,
entrepreneurship, project management, operations, sales, human resources, and other ordinary
professional contexts.

## 5. Professional elements to strengthen

### 5.1 Start from work rather than output taxonomy

The opening should quickly move from:

```text
What can generative AI produce?
```

to:

```text
What work are you trying to get done?
```

The learner should identify the task before selecting the output.

Examples may include:

- drafting a customer email;
- rewriting a message for another audience;
- turning authorized notes into a meeting summary;
- structuring a report;
- preparing a presentation outline;
- creating a communication visual;
- preparing a simple technical aid.

### 5.2 Everyday text transformation

Text should become the principal professional entry point because it supports recognizable tasks
without requiring specialized software or technical knowledge.

S02 should explicitly show that generative AI can assist with:

```text
DRAFT
REWRITE
SUMMARIZE
ORGANIZE
REFORMAT
ADAPT TO AN AUDIENCE
```

The distinction between transformation and invention must be visible.

### 5.3 Email and professional messaging

Learners should see a simple example in which AI helps:

- organize a message;
- improve clarity;
- adjust tone;
- shorten or expand a draft.

The result remains a draft.

Before sending, a person should verify relevant details such as:

- names;
- dates;
- amounts where applicable;
- commitments;
- attachments or referenced documents.

S02 should teach the professional use pattern without yet teaching the full S03 prompt framework.

### 5.4 Meeting notes and summaries

A meeting-summary example should reinforce a strong source boundary.

If supplied notes do not identify:

- a responsible person;
- a deadline;
- a decision;

the generated summary must not invent one.

The professional lesson is:

```text
MISSING IN SOURCE
        ≠
PERMISSION TO COMPLETE BY GUESSING
```

Detailed document-analysis techniques remain for S04.

### 5.5 Reports and presentations

S02 should show that generative AI can help structure supplied information into:

- a report outline;
- a briefing;
- a presentation outline;
- a proposal structure.

The learner should understand that good organization does not establish factual accuracy.

Any claim in the resulting document still requires support.

### 5.6 Rewrite without changing meaning

The current S02 already adapts one instruction to another audience.

This should be broadened into a general professional principle:

> Change the form without silently changing the facts.

Possible transformations include:

```text
NOTES → SUMMARY
LONG MESSAGE → SHORT MESSAGE
INTERNAL WORDING → CLIENT-FACING WORDING
SOURCE INFORMATION → PRESENTATION OUTLINE
TECHNICAL WORDING → PLAIN-LANGUAGE EXPLANATION
```

### 5.7 Transfer beyond the cooperative

The cooperative should remain the continuous case study.

At least one compact transfer sequence should make the same principles recognizable in other
professional contexts.

Examples may include:

- administration: turn approved notes into a structured memo;
- customer service: rewrite a factual response in a clearer tone;
- project management: organize supplied meeting notes;
- sales: prepare a presentation outline from approved product information;
- human resources: reformat an approved internal announcement without inventing policy.

These are teaching contexts, not claims that a particular organization uses AI this way.

### 5.8 Verification as part of generation

The existing three-check structure remains useful:

```text
FACTS
AUDIENCE / USE
AUTHORITY
```

It should be presented as part of the normal task rather than a separate safety lecture.

A generated result is not complete merely because it is fluent.

### 5.9 Confidentiality as an operating habit

S02 should reinforce, without duplicating S06, that learners use:

- fictional information;
- anonymized information;
- public information;
- explicitly authorized information.

The session must not require real customer, employee, member, payment, medical, financial, or
confidential organizational data.

### 5.10 Value without invented benefits

The current measurement slide should remain.

Learners may define possible indicators such as:

- preparation time;
- factual accuracy;
- corrections required;
- consistency;
- usefulness to the intended audience.

They must not present an expected improvement as an observed result.

## 6. Material to compress or move to notes

S02 must remain accessible and professionally oriented.

The following material may remain in the canonical notes or presenter notes when it is not required
for the main learning objective.

### Output-family taxonomy

The seven output families remain part of the canonical source.

They should be introduced compactly rather than becoming the organizing principle of the session.

### Model-family and historical detail

Detailed model-family evolution is not required for S02's professional objective.

S01 already establishes the conceptual progression toward foundation models.

### Named tools and provider comparisons

Product catalogues, current pricing, quotas, rankings, and tool comparisons should remain outside
the main projected sequence unless independently sourced and specifically required.

S02 teaches task selection and review, not product shopping.

### Detailed media-production workflows

Image, audio, and video generation remain useful examples.

They do not need separate procedural tutorials.

The professional lesson is the type of output and the type of verification required.

### Detailed coding instruction

Generated code should remain a bounded example.

S02 does not become a programming class.

The learner only needs to understand that plausible code still requires execution, testing,
security review, and appropriate technical ownership.

### Deep agent design

Agentic AI remains an introductory distinction.

Architecture, orchestration, permissions design, and autonomous-system engineering remain outside
S02.

## 7. Boundaries with later sessions

The professional fusion must not make S02 absorb the rest of the curriculum.

### S03 — Designing Effective Prompts

S02 may show simple task instructions.

It should not teach in depth:

- the seven-element prompt framework;
- zero-shot versus few-shot prompting;
- interviewing;
- decomposition;
- alternative formulations;
- systematic prompt evaluation.

Those belong to S03.

### S04 — Working with Documents and Information

S02 may introduce:

- summarizing supplied notes;
- restructuring supplied information;
- identifying missing facts.

It should not become the full source-grounded document-analysis session.

Detailed summarization, comparison, extraction, and information verification belong to S04.

### S05 — Building an AI-Assisted Workflow

S02 may show that generation fits inside:

```text
TASK → DRAFT → REVIEW → USE
```

It should not teach complete workflow mapping, reuse strategy, governance checkpoints, or detailed
value measurement.

Those belong to S05.

### S06 — Security, Privacy, and Responsibility

S02 should reinforce safe information habits and human approval.

It should not attempt the full security, confidentiality, privacy, and consequential-decision
curriculum.

### S07 — End-to-End Professional Workshop

The S02 activity should remain bounded to one use case and one output.

It should not become the complete capstone process.

## 11. Proposed professional transfer sequence

The central transfer sequence should become:

```text
WHAT WORK NEED DO I HAVE?
        ↓
WHAT SHOULD THE AI PRODUCE?
        ↓
WHAT INFORMATION MAY IT USE?
        ↓
WHAT MUST THE OUTPUT PRESERVE?
        ↓
WHAT MUST I CHECK?
        ↓
WHO MAY USE OR APPROVE IT?
```

This sequence anticipates the program-wide five-question framework without teaching the full S03
prompt structure prematurely.

## 12. End-of-session transfer check

S02 should end by asking:

```text
WHAT DID I LEARN?
WHERE COULD I USE IT?
WHAT MUST I CHECK BEFORE I USE IT?
```

A learner should be able to answer with a task from their own professional context rather than only
the cooperative case.

A strong S02 outcome is not:

> I know seven types of generative output.

A stronger outcome is:

> I can identify a bounded work task, choose an appropriate generated output, preserve the supplied
> facts, review the result, and identify the person responsible for using or approving it.

## 13. S02 scope boundary

S02 teaches professional generative-AI use at the level of task, output, transformation, and
review.

It does not attempt to teach:

- detailed prompt engineering;
- complete document-analysis methods;
- full workflow engineering;
- formal privacy or security governance;
- autonomous-agent architecture;
- programming;
- product comparisons;
- the final end-to-end professional capstone.

These remain available to later sessions or reference material.

## 15. Audit conclusion

The existing S02 should be refactored rather than replaced.

Its strongest existing elements are:

- clear distinction between generation and other AI tasks;
- a bounded source-grounded demonstration;
- an observable unsupported claim;
- correction against the supplied source;
- explicit human authority;
- multimodal and code exposure;
- measurable-use framing.

The professional fusion should preserve those strengths while changing the session's center of
gravity.

The revised S02 should move from:

```text
GENERATIVE AI CAN PRODUCE MANY OUTPUT TYPES
```

toward:

```text
GENERATIVE AI CAN HELP WITH RECOGNIZABLE PROFESSIONAL TASKS
        ↓
THE OUTPUT IS A DRAFT
        ↓
PRESERVE THE SOURCE
        ↓
CHECK BEFORE USE
        ↓
A PERSON REMAINS RESPONSIBLE
```

That creates the intended bridge from S01's AI literacy to S03's detailed prompt design.
